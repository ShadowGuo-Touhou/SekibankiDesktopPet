# 契约 · 窗口模式接口（PetMode）

> 目的：把"宠物如何在屏幕上被实现出来"这件事收敛到**一个接口**后面，让工具栏模式和全屏模式各自实现，
> 主流程（`DesktopPet`）与嵌套子系统（游走、对话泡）**不再出现任何模式判断**。
>
> 本文只定**契约与迁移步骤**，不含实现。你审完再动代码。

---

## 一、判据

一条能力进接口，必须同时满足：

1. **能用"用户意图"命名**——不是"某个模式的实现步骤"。反例：`dragExitPos()`（工具栏模式特有动作）。
2. **两种模式的实现真的不同**。相同的一律放基类做默认实现，不进抽象方法。

> 参考先例：PlasmaZones 的 `IPlacementEngine`——snap 与 autotile 两套算法共用一份接口，上层做到
> "zero mode branches"，并且把方法分成 **REQUIRED（纯虚）** 和 **OPTIONAL（安全空实现）** 两档。

## 二、文件布局

| 文件 | 内容 | 状态 |
|---|---|---|
| `PetMode.py` | **只放接口**（抽象基类 + 有默认实现的公共方法） | 新建 |

**为什么用继承而不是一个类里 `if`**：你说过两个模式要拆成两个文件。两个文件 + 一份抽象基类 =
多态派发，主流程只写 `self._mode.xxx()`，没有一处 `if mode == ...`。
"在接口内根据是否为工具栏模式调用对应功能"这件事，由**每个实现自己**决定——这就是接口的意义。

## 三、坐标系约定（这是整份契约的地基）

**唯一事实来源：宠物贴图左上角在屏幕上的坐标。**

| | 工具栏模式 | 全屏模式 |
|---|---|---|
| 窗口 | 边长 `windowSide` 的方块，跟着宠物跑 | 固定 = 主屏，永不移动 |
| 宠物位置 | = 窗口位置 + `spriteInset` | = 窗口内的一个坐标 |
| `pos()` | 有意义 | **恒为 (0,0)，无意义** |

**契约里不许出现"窗口坐标"**。所有进出接口的位置都是**屏幕坐标**，且指的是**宠物贴图左上角**，
不是窗口左上角。这一条决定了游走线程、设置菜单、对话泡三处怎么改。

## 四、接口契约

### 4.1 生命周期

```python
def __init__(self, pet) -> None
    """pet: DesktopPet。模式需要读 ORGINALWIDTH/_petImageSize/petImage/petLabel/_dragAngleDeg，
    也需要调用窗口自己的 move/resize/setGeometry/update。"""

def configureWindow(self) -> None
    """按模式决定窗口的 flags 与尺寸。启动时调用一次。
    工具栏：FramelessWindowHint | WindowStaysOnTopHint | (Window 或 SubWindow)，尺寸 = windowSide
    全屏：  FramelessWindowHint | WindowStaysOnTopHint | Window，尺寸 = screenRect()"""

def applyScale(self, at: QPoint = None) -> None
    """贴图缩放(_petImageSize)变化后的重新布局。
    参数 at：顺便把窗口挪到这个屏幕坐标（仅启动时用，避免"先 resize 后 move"两次 SetWindowPos 的闪帧）。
             全屏模式忽略它。
    工具栏：重算 windowSide / spriteInset，setScaledSize，resize/setGeometry，重排 petLabel
    全屏：  只 setScaledSize + 重排 petLabel，窗口不动"""
```

### 4.2 位置

```python
def petRect(self) -> QRect
    """宠物贴图当前占据的屏幕矩形（未旋转）。唯一事实来源的读出口。"""

def placePetAt(self, x: int, y: int) -> None
    """把宠物贴图左上角放到屏幕坐标 (x, y)。
    工具栏：move(x - spriteInset, y - spriteInset)
    全屏：  _spritePos = (x, y)，移 label，局部重绘

    注意：这是"移动宠物"，不是"移动窗口"。工具栏模式里二者等价，全屏模式里只有前者存在。"""

def randomPetPos(self) -> QPoint
    """屏幕内一个随机的、保证整只宠物不出屏的落点（宠物左上角）。"""
```

### 4.3 查询

```python
def screenRect(self) -> QRect                      # 基类默认实现，两种模式相同
    """宠物可用的屏幕区域（只认主屏）。替代散落 8 处的 WINDOWWIDTH/WINDOWHEIGHT。"""

def petRect(self) -> QRect
    """宠物贴图当前的屏幕矩形（**未旋转**，屏幕坐标）。

    ★ 定位类消费者全用它：游走边界、对话泡定位、设置菜单贴边、传送落点。
      **拖拽期间它也返回未旋转的图片矩形**——旋转包围盒会随摆动角度抖动，
      拿它定位会让气泡上下抖。
    """

def petBounds(self) -> QRect
    """宠物当前的**旋转包围盒**（屏幕坐标）。

    只在"别让宠物跑出屏幕"这类**守卫**逻辑里用（拖拽夹取）。
    与 petRect() 是两套，各司其职，不许混用。
    """
```

> **两套矩形并存是有意的**：定位要稳（图片矩形），守卫要严（包围盒）。
> 已定：拖拽夹取用 `petBounds()`，其余一律 `petRect()`。见第七节。

### 4.4 拖拽

```python
def prepareDrag(self, grabGlobalPos: QPoint) -> None
    """鼠标按下：进入拖拽准备态。**不得移动宠物或窗口**（这是"点一下不跳"的保证）。
    工具栏：_dragRadius = windowSide//2；_spriteOrigin = (inset, inset)；_pivotOffset = 抓取点(窗口坐标)
    全屏：  _pivotOffset = 抓取点(宠物本地坐标)；没有 _dragRadius"""

def followCursor(self, cursorScreenPos: QPoint) -> None
    """拖拽跟随：把旋转枢轴停到光标下，并把整只宠物夹在屏幕内。
    工具栏：算窗口该在哪 → placePetAt
    全屏：  算贴图该在哪 → placePetAt"""

def endDrag(self) -> None
    """退出拖拽的**几何收尾**。
    工具栏：dragExitPos() + placePetAt()（两个函数都收进本文件）
    全屏：  空实现（没有窗口要回位）

    【本契约最重要的一条】主流程只调这一个方法，不再自行编排"先算位置、再清状态、再移动"。"""

def isDragging(self) -> bool
    """当前是否处于「按拖拽方式绘制」的状态。
    替代今天用 _dragRadius is not None 当开关的三处（paintEvent / _frame_has_passed / _petDraggedMove）。"""

def spriteOriginInWindow(self) -> QPoint
    """paintEvent 画旋转贴图时，(0,0) 对应窗口里的哪个点。"""

def pivotInWindow(self) -> QPoint
    """paintEvent 的旋转枢轴，窗口坐标。"""
```

### 4.5 显示

```python
def setPetVisible(self, visible: bool) -> None     # 基类默认：窗口透明度（两种模式行为一致）
def refresh(self, rect: QRect = None) -> None      # 基类默认：pet.update(rect)
    """工具栏模式整窗重绘无所谓；全屏模式**必须**传 rect 走局部重绘——面积从 1242² 变成 4K，
    不局部重绘 CPU 会明显上去。"""
```

| 你的 # | 接口 | 属于 | 落地 |
|---|---|---|---|
| 1 | `placePetAt(x, y)`——**宠物左上角的屏幕坐标**（不是窗口坐标） | 位置 | `a5666d9` |
| 2 | `petRect()` | 位置 | `a5666d9` |
| 3 | ~~`petExtents()`~~ → 拆成 **`petRect()` / `petBounds()`** 两个，分工见 7.2 | 查询 | `a5666d9` |
| 4 | `screenRect()`（基类默认实现） | 查询 | `a5666d9` |
| 5 | `applyScale(at=None)` | 生命周期 | `a5666d9` |
| 6 | 拖拽状态收进 TrayMode + `isDragging()` 取代它当开关 | 拖拽 | `43c69d2` |
| 7 | `followCursor(cursor)` | 拖拽 | `a5666d9` |
| 8 | `endDrag()`——自己算位置、移窗口、**并清掉自己的拖拽状态** | 拖拽 | `a5666d9`＋`43c69d2` |
| 9 | `configureWindow()` | 生命周期 | `a5666d9` |
| 10 | `spriteOriginInWindow()` + `pivotInWindow()` | 拖拽 | `a5666d9` |
| ＋ | **`grabPointInSprite()`** ← 计划外，动手做第 6 条时才发现 | 拖拽 | `43c69d2` |

`grabPointInSprite()` 是这份契约里唯一一个**写计划时没想到**的方法：

`_changeDragAngle` 要算"她被吊起来时的起始摆角"，而那个角是"从贴图中心指向抓取点"
的向量角。抓头顶和抓脚底，挂起来的姿态完全不同。原来的代码是主流程自己拿
`_drag_pos - _spriteInset` 算的——**那是主流程在替模式做坐标换算**，正是你一开始
指出的毛病。所以它必须变成接口：工具栏模式减内缩，全屏模式减贴图在窗口里的位置。

**不在接口里**（两种模式一致，或与模式无关）：`grabMouse/releaseMouse`、`_dragPixmaps`、
`_swing`/`DragSwing`、`_dragAngleDeg`、`_frame_has_passed` 的判定规则、音效、点击压扁、托盘菜单、对话系统。

## 五、第 6 条的专项记录（`_dragRadius` 归位）—— 已完成

你特别指出这条"涉及多处重构"。`_dragRadius` 一个变量当初担了两个职责：

| 职责 | 原来用在哪 | 归位后 |
|---|---|---|
| **工具栏几何**：窗口半边长，旋转枢轴用 | `beginDrag` / `extents` / `followCursor` | 删了——不再是几何量 |
| **通用开关**：当前是否处于拖拽绘制态 | `paintEvent` / `_frame_has_passed` / `_petDraggedMove` / `_endDrag` | → `isDragging()` |

**实际做法与计划的三处出入：**

1. 没有保留"转发属性"过渡。三个消费者（气泡、游走、抓取角）在 `a5666d9` 里已经
   全部改走接口，转发属性一个用户都不剩，所以在 `43c69d2` 里直接删掉，没有中间态。
2. `_dragRadius` 不是"搬进 TrayMode"，而是**消失了**。它唯一的存在理由是"窗口半边
   长"，而拖拽期间已经没有任何东西需要知道窗口半边长——旋转枢轴就是抓取点本身。
   取而代之的是一个明确的布尔 `dragging`。
3. **`_spriteOrigin` 被证明是死的。** 它恒等于 `(spriteInset, spriteInset)`，而
   `_endDrag` 里的用法是 `pos + spriteOrigin - spriteInset` = `pos`。也就是说那个
   "贴图从拖拽位置回到站立内缩"的补偿量**恒为 0**——它是"窗口曾在拖拽期间改尺寸"
   那个年代的遗物。删掉，并且用一条验收钉住它确实为 0。

`_drag_pos` / `_pivotOffset` 合并成 `grabPoint` 一个字段（它们本来就存的是同一个值）。

## 七、统一规则（已定，已实施）

### 7.1 规则：「一切都以图片矩形为准」

游走边界、对话泡定位、设置菜单贴边、传送落点、拖拽跟随的边界——**全部**以 `petRect()` 为准，
**拖拽期间也一样**（不换成旋转包围盒）。

这条规则一确立，上一版里那两处"需签字的行为变化"就不再是两个独立决定，而是**同一条规则的自然结果**：

| 原来列的变化 | 现在是 |
|---|---|
| 游走边界从 `[-inset, 屏宽-side-inset]` 变成 `[0, 屏宽-spriteW]` | 就是"按图片矩形判定" |
| `randomPetPos` 从按窗口尺寸改成按贴图尺寸 | 同上 |

**附带收益**：对话泡以前要等松开（`_dragRadius is None`）才敢显形，因为按下时 `_spriteExtents()`
会给出错的位置。改用 `petRect()` 后，**按下期间的位置也是对的**，那条等待可以去掉，
`placeBubble` 里偷看 `mainWindow._dragRadius` 的代码也一并消失。

### 7.2 夹取用旋转包围盒（已实施）

**拖拽时的边界夹取用旋转包围盒**，摆动多厉害都不让宠物露出屏幕外。
它是各模式的私有方法——工具栏里叫 `reachFromPivot()`，**不进接口**。

对外暴露的绝对包围盒是 `petBounds()`：它拿 `reachFromPivot()` 的枢轴相对量，加上枢轴
的屏幕位置，换算成屏幕矩形。**向外取整**（floor / ceil）——一个说自己盖住了却少一像素
的盒子就是在撒谎（这个缺陷是写验收脚本时抓出来的）。

于是项目里存在**两套"宠物在哪"**，各司其职：

| 用途 | 用哪套 | 谁用 |
|---|---|---|
| **定位**（气泡贴头顶、菜单贴边、传送、游走边界） | **图片矩形**（未旋转） | 对话泡、设置菜单、游走、`randomPetPos` |
| **守卫**（别让宠物跑出屏幕） | **旋转包围盒** | 拖拽夹取（私有）、`petBounds()`（对外） |

> 另：`tests/test_click_behavior.py` 里 `release flips facing direction` 是**既有 flaky**
> （初始朝向 `random.randint(0,1)`，约 50% 概率失败），与本重构无关。迁移期间以"失败条
> 是否只是它"作为回归判据。
